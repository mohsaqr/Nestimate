Scope and method

CRAN’s published package reference identifies 0.9.24, published 7 October 2026. The local 0.9.24 commit was used as the source comparison baseline; the CRAN source tarball was not independently compared byte for byte. Current source contains 86 R files and 51,766 lines including documentation. The baseline-to-HEAD diff changes 40 R files; across package code, documentation and tests it spans 111 files, 10,923 insertions and 1,039 deletions.

The review combined the post-CRAN source diff, broad module inspection, synthetic counterexamples, explicit controls, existing test execution, source-package construction, and R CMD check. Three parallel reviews were used under the repository’s inherited AGENTS.md instruction: sequence/input handling, inference/higher-order methods, and older estimation/clustering/MCML code. The primary reviewer separately examined the new landscapes and reran every reported defect from retained scripts. Prior audit notes were treated as leads, not as proof that an issue remained open.

This is broad review coverage with deeper scrutiny of changed code, not a claim that every one of 51,766 lines received equal inspection or that every statistical procedure was independently rederived. Static test mentions are an inventory aid, not measured code coverage. No fresh coverage percentage is claimed.

R01 · P1 — Numeric sequences with a logical missing position become ID sequences

Post-CRAN; incomplete input correction
R/build_network.R:1543–1551; R/extract_sequences.R:124

Before fix. For id=s1/s2, numeric T1/T3 and T2=NA, extraction returns id and T2. The resulting network has nodes s1 and s2; the actual states are metadata. This silently affects core estimation and every new sequence verb.

Original cause. The numeric position-run detector requires is.numeric() for every position. An all-missing column created with NA is logical. The analogous categorical detector allows all-missing positions, but this branch does not.

Original review recommendation. Allow all-missing columns within an otherwise numeric position run, while requiring evidence of numeric positions. Until fixed, supply cols=c("T1","T2","T3").

Regression test. Assert inferred and explicitly selected state matrices agree for numeric positions plus logical NA, with an ID column present. Check node labels as well as output dimensions.

d <- data.frame(id=c('s1','s2'), T1=c(1,2), T2=NA, T3=c(2,1))
extract_sequences(d)
build_network(d, method='relative')$nodes

Retained evidence: sequence-repros.R; sequence-repros.log

Resolved. Requested covariates are removed before distance calculation; external frames preserve unrelated same-name positions. Regression coverage: tests/testthat/test-fix-review-models.R.

R02 · P1 — Post-hoc covariates determine the clusters they are tested against

Pre-existing at CRAN baseline; freshly reproduced
R/cluster_data.R:679–680, 738, 779–783

Before fix. Eight identical A→B sequences split perfectly into H and L groups when outcome is included in the raw frame and supplied as a post-hoc covariate. The function then reports outcomeL odds ratio 81. In this toy example the p-value is .0623; no significant result is claimed.

Original cause. The entire raw data frame reaches sequence encoding and distance calculation before covariates are resolved. Outcome is treated as an extra sequence position, manufacturing the clustering signal. This violates post-hoc semantics.

Original review recommendation. Resolve and remove named covariates before encoding, retain them separately, and preserve alignment. A network with covariates already in metadata, or a separate covariate data frame with sequence-only input, avoids this trigger.

Regression test. Changing a post-hoc covariate must leave the sequence distance matrix unchanged. Include constant true sequences and categorical/numeric named covariates.

d <- data.frame(V1=rep('A',8), V2=rep('B',8),
                outcome=rep(c('H','L'),each=4))
f <- build_clusters(d,k=2,covariates='outcome')
f$assignments # 1 1 1 1 2 2 2 2

Retained evidence: broad-repros.R; broad-repros.log

Resolved. Fits retain the weighting specification and bootstrap draws replay it, including custom schemes and factor options. Older custom fits without a specification request a rebuild. Regression coverage: tests/testthat/test-fix-review-models.R.

R03 · P1 — Loading uncertainty uses strength weights for an equal-weight fit

Pre-existing; earlier audit §6.2, still reproducible
R/mcml_pc.R:880–889

Before fix. An equal-weight composite has six observed loadings of 1/3. loading_stability() returns means .40279, .40214, .19507, .39981, .39849 and .20170; all six observed weights lie outside their bootstrap intervals. With fixed equal weighting, the resampled weights should remain 1/3.

Original cause. Resamples call .pc_network_loadings() directly and do not replay x$meta$weighting or the weighting transformation. Confidence intervals therefore describe a different estimator. This also requires attention for eigen, factor and custom weighting.

Original review recommendation. Replay the fitted weighting scheme in each resample. Preserve fixed weights for equal/custom schemes and refit only data-dependent schemes using their original settings.

Regression test. For equal weights, assert every draw is 1/cluster_size and bootstrap SD is zero. For fitted schemes, compare a deterministic resample with an explicit full rebuild.

# Full deterministic n=4000 fixture is in the evidence script.
f <- build_mcml_pc(d, clusters, aggregation='composite',
                   weighting='equal',method='cor',cor_method='pearson')
loading_stability(f,iter=30,seed=3)$summary

Retained evidence: broad-integration-repros.R; broad-integration-repros.log

Resolved. Generated responses are held separately from metadata, protecting .outcome adjustments and grouping columns. Regression coverage: tests/testthat/test-fix-review-sequences.R.

R04 · P2 — Pattern outcome overwrites a real adjustment named .outcome

Post-CRAN new function; incomplete name-collision protection
R/pattern_outcome.R:150, 159

Before fix. For the same 39-row data, the pattern coefficient is .9285199 when adjusting for score. Renaming score to .outcome changes the coefficient to 8.9e-12. The function has replaced the adjustment with the outcome itself.

Original cause. Vector and last_obs outcomes are written into units$.outcome before adjustment/group columns are extracted. Later internal model-column renaming protects other names but occurs too late for this collision.

Original review recommendation. Keep the response separately or allocate a collision-free temporary name before modifying units. This also protects a grouping column named .outcome.

Regression test. Assert fitted coefficients are invariant when adjustment/group columns are renamed, including .outcome, for explicit vector and last_obs outcomes.

Retained evidence: sequence-repros.R; sequence-repros.log

Resolved. Named axes are validated and aligned; incompatible named sets are rejected. Unnamed inputs retain positional matching. Regression coverage: tests/testthat/test-fix-review-models.R.

R05 · P2 — Comparisons ignore node names when matrix orders differ

Pre-existing; earlier audit §4.3, still reproducible
R/compare_network.R:149–158

Before fix. Comparing a named matrix with a simultaneous row/column permutation of itself produces mean absolute difference 1.7777778 and Pearson .3809524, although both encode the same graph. Different named node sets of equal size are also accepted.

Original cause. Only dimensions are validated; subtraction and correlation use matrix positions. Reordering a correctly labelled input silently changes the result.

Original review recommendation. Align equal named node sets before computing statistics, and reject incompatible named sets. Retain a documented positional fallback for unnamed inputs.

Regression test. Compare a graph to its reordered self: all differences zero, Pearson one. Add incompatible-node and one-unnamed-input controls.

W <- matrix(c(0,1,2,3,0,4,5,6,0),3,3,byrow=TRUE,
            dimnames=list(LETTERS[1:3],LETTERS[1:3]))
compare_model(W,W[c(3,1,2),c(3,1,2)],network=FALSE)

Retained evidence: broad-integration-repros.R; broad-integration-repros.log

Resolved. Ordinary Gaussian intervals use residual-df Student t quantiles, matching their displayed tests. Regression coverage: tests/testthat/test-fix-review-models.R.

R06 · P2 — Gaussian confidence intervals conflict with the displayed t tests

Pre-existing; earlier audit §5.12, still reproducible
R/outcome_model.R:249, 256–257

Before fix. For six observations, slope .6 has SE .2390457 and p=.06605877. The displayed nominal 95% interval [.131479,1.068521] excludes zero; the ordinary linear-model t interval is [-.06369732,1.26369732].

Original cause. The Gaussian GLM estimates dispersion and reports Student t p-values. The effect-table code always uses qnorm() for intervals, yielding narrower intervals at small residual degrees of freedom.

Original review recommendation. Use the appropriate residual-df t quantile for ordinary Gaussian fits. Treat binomial and mixed-model approximations explicitly.

Regression test. Compare ordinary Gaussian intervals against confint(lm(...)) across residual degrees of freedom; check consistency between zero inclusion and the unadjusted two-sided test.

d <- data.frame(x=1:6)
d$y <- .6*d$x+c(1,-1,0,0,-1,1)
outcome_model(d,'y','x',family='gaussian')$effects
confint(lm(y~x,d))

Retained evidence: broad-repros.R; broad-repros.log

Resolved. Tensor directions use log-space products and stable normalization, including 150/400-node and asymmetric analytic controls. Regression coverage: tests/testthat/test-fix-review-higherorder.R.

R07 · P2 — Z centrality silently underflows to zero for large hyperedges

Post-CRAN numerical regression
R/hypergraph_centrality.R:251–257, 272–274

Before fix. A single uniform hyperedge of 150 nodes returns every Z entry as 7.606786e-163 and an L2 norm of zero, with no warning. The symmetry solution is 1/sqrt(150)=.08164966 per node. At 400 nodes all entries are zero.

Original cause. The rewritten iteration squares a tiny tensor product before shifting/rescaling. Those squares underflow, and a zero norm is mistaken for an absent tensor. The earlier shift-first kernel preserves the symmetric solution on this example; that does not establish its correctness for all large graphs.

Original review recommendation. Use stable normalization and scaled/log-domain products where needed; distinguish a true zero tensor map from floating-point underflow.

Regression test. Check analytic uniform solutions at 150 and 400 members and nonuniform rankings on an asymmetric large uniform graph. Assert nonzero unit norm and honest convergence diagnostics.

hg <- bipartite_groups(data.frame(player=1:150,group='G'),'player','group')
z <- hypergraph_centrality(hg,type='Z')$Z
range(z); sqrt(sum(z^2))

Retained evidence: inference-repros.R; inference-repros.log

Resolved. Landscapes replay weighting, concatenation and markers before counting; bootstrap units are merged sequences. Covariate conflicts and unrepresentable transformed chains produce informative errors. Surface stability measures retain every prepared position, including start markers. Regression coverage: tests/testthat/test-fix-review-landscapes.R.

R08 · P2 — Landscapes silently discard network weighting and concatenation

Post-CRAN new feature
R/stability_landscape.R:55–62, 90–95, 268–270

Before fix. A weighted transition network has A stay probability 1/3, but its landscape reports .4. A concat=3 network has stays A=2/3 and B=1/2, but its landscape reports .5 and 0. The discrepancy changes expected stays and depths. Landscape surfaces and trends use the same raw-sequence path.

Original cause. The landscape reads stored sequences and pools unweighted adjacent counts without replaying build_args/params. Weighting changes the estimand; concatenation also changes transitions and the bootstrap units. The API describes a landscape of the supplied transition network.

Original review recommendation. Faithfully replay supported estimation settings, or explicitly reject models with unsupported settings and document the required raw-data estimand. Do not silently return another chain.

Regression test. Assert full-length landscape stays agree with diag(network$weights) for weighted and concatenated fits, and verify bootstrap units/settings against an explicit reconstruction.

d <- data.frame(T1=c('A','A','B'),T2=c('A','B','A'))
n <- build_network(d,method='relative',params=list(concat=3))
diag(n$weights)
summary(stability_landscape(n,iter=0))[,c('state','stay')]

Retained evidence: landscape-probes.R; landscape-probes.log; landscape-extra.log

Resolved. Nonconstant measures and covariates with identical trimmed endpoints use their full range; both surface plots execute. Regression coverage: tests/testthat/test-fix-review-landscapes.R.

R09 · P2 — A nonconstant measure can create a collapsed surface axis and crash

Post-CRAN new feature
R/stability_landscape.R:447–451, 650–669, 692

Before fix. With 21 valid sequences, 20 alternating A/B and one A/A/B/A, entropy varies but its 5th and 95th percentiles are both 1. landscape_surface() returns 25 copies of one slice; plot() fails with invalid y argument.

Original cause. Validation checks the full measure range, but the grid uses trimmed quantiles. Those endpoints can coincide for a discrete, strongly tied measure. Plotting deduplicates the values to one y coordinate, which persp() cannot render as a surface.

Original review recommendation. Validate the actual grid endpoints; use a documented fallback range, a one-slice display, or a classed informative error. Avoid returning a nominal surface that its plot method cannot draw.

Regression test. Test nonconstant measures whose trimmed quantiles coincide. Check both summary semantics and plot execution, alongside constant-measure and ordinary continuous-measure controls.

s <- as.data.frame(matrix(rep(c('A','B','A','B'),each=21),nrow=21))
s[21,] <- c('A','A','B','A')
a <- landscape_surface(s,k=5)
plot(a) # invalid y argument

Retained evidence: landscape-probes.R; landscape-probes.log

Resolved. MOGen summary preserves numeric layer/cumulative DOFs above the integer limit. Regression coverage: tests/testthat/test-fix-review-higherorder.R.

R10 · P2 — MOGen summaries overflow the new double-precision parameter counts

Post-CRAN integration regression
R/mogen.R:768–769

Before fix. A valid 10-state fit through order 10 stores finite path DOFs of 9e9 and 9e10 for its last two layers. summary() returns NA for those layer counts and produces integer-coercion warnings. Model criteria remain finite; this finding concerns summary output rather than invalid fitting.

Original cause. New path-based DOFs intentionally use doubles, but existing summary code casts them back to 32-bit integers. The new parameter-count representation was not propagated through the reporting API.

Original review recommendation. Preserve numeric DOF columns in summaries and formatting. Check both layer and cumulative parameter counts.

Regression test. Include a small valid fit with parameter counts above .Machine$integer.max; assert returned counts match stored values without warnings.

set.seed(4)
s <- replicate(100,sample(LETTERS[1:10],14,TRUE),simplify=FALSE)
m <- build_mogen(s,max_order=10)
tail(m$layer_dof,2); tail(summary(m)$layer_dof,2)

Retained evidence: inference-repros.R; inference-repros.log

Resolved. Scale-sensitive constant-vector detection preserves normalization of small, nonconstant values. Regression coverage: tests/testthat/test-fix-review-models.R.

R11 · P3 — Small but nonconstant strengths normalize to NaN

Post-CRAN numerical edge case
R/centrality_measures.R:222–229

Before fix. Public net_centrality() reports distinct incoming strengths of approximately 3e-12,1e-12,2e-12 but returns NaN for every normalized strength. The trigger involves extreme dwell/exit ratios and is lower priority than ordinary-input defects.

Original cause. The new constant-vector tolerance is 1e-10 times max(abs(endpoints),1). The unit floor imposes an absolute threshold and classifies substantial relative variation at a small scale as constant.

Original review recommendation. Use a scale-sensitive tolerance and handle exact constant vectors separately. Preserve min-max normalization under positive common rescaling.

Regression test. Test c(1,2,3) multiplied by several positive scales, plus exact-constant and rounding-noise vectors.

Retained evidence: broad-repros.R; broad-repros.log

Resolved. Stars-only literal states are explicitly reserved and rejected with documented nestimate_bad_input; ordinary embedded stars remain valid. Regression coverage: tests/testthat/test-fix-review-sequences.R.

R12 · P3 — Literal stars-only states collide with pattern wildcard parsing

Post-CRAN new function
R/sequence_patterns.R:463–464, 496

Before fix. Extraction accepts ** as a literal state. Unigram mining then raises an unclassed vapply error; bigram **→B receives lift .5 when its presence support .5 and state supports .5 and 1 imply lift 1.

Original cause. The pattern parser removes stars-only tokens regardless of whether they were observed state labels or inserted wildcard positions.

Original review recommendation. Either reserve/reject stars-only labels with a documented classed error or keep wildcard positions structurally distinct from state labels.

Regression test. Include ** and *** literals in unigram and bigram discovery, plus real gapped-pattern controls. Assert a correct result or a documented validation error.

d <- data.frame(T1=c('**','A'),T2=c('B','B'))
sequence_patterns(d,len=1,min_freq=1,min_support=0)
sequence_patterns(d,len=2,min_freq=1,min_support=0)

Retained evidence: sequence-repros.R; sequence-repros.log

Resolved: reliability of existing edges versus the whole graph

Implemented: casedrop_reliability(target = "auto") uses existing edges for unscaled/unthresholded transition methods and all cells for association or transformed networks. Explicit "existing" and "all" select either target; the resolved target is stored in each result. The original reproducer now agrees with the whole-graph maximum deviation. Coverage: test-fix-review-higherorder.R. The next paragraphs describe the original limitation.

R/casedrop_reliability.R:175–177 restricts the edge vector to cells nonzero in the original graph. The stated motivation—that subsampling cannot create an absent transition—holds for unthresholded transition counts. It does not hold for association or thresholded graphs. A deterministic thresholded-correlation example gains V1–V4=.3029003 and V3–V4=.2933043 after case removal. Reported max_abs_dev is .2854884 while whole-graph maximum deviation is .3029003. See inference-repros.R and its log.

At review time the help explicitly described present-edge-only metrics, so this is kept outside the 12 defects: it is an implemented target with a material limitation. The new target option and method-aware default now make this distinction explicit.

Compatibility and release readiness

The documented 1.0.1 migration notes for plot_mosaic, sequence_plot argument positions and hypergraph_centrality defaults remain in effect. These fixes add explicit behavior: stars-only literal state labels are reserved by the pattern syntax and now raise nestimate_bad_input; older saved custom-weight composite fits need rebuilding to retain their weighting specification; and landscape inputs must represent their stored sequence chain. The new case-drop auto target includes potentially emerging association edges.

All five previously omitted pkgdown topics have been added to the reference index. A push/PR workflow now configures the full development suite and package checks on Linux, macOS and Windows. The workflow was parsed locally but has not been run on GitHub. No full pkgdown site rebuild, minimum-dependency matrix, PDF manual build or release deployment is claimed.

Before release, inspect CI on the supported platforms and check minimum dependency versions. The current work addresses all reported defects; these broader release checks remain environment validation rather than unresolved findings.
