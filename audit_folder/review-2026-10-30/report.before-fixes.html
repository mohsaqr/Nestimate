Nestimate: extensive code review

30 October 2026 · Source version 1.0.1 · HEAD dcdd7135 · CRAN comparison baseline 0.9.24 / 74617a5e

12 reproduced defects: 3 high priority, 7 medium priority, and 2 low priority. Eight affect code added or changed after CRAN; four are older defects that remain reproducible. Fix the three high-priority issues before relying on the affected workflows.

This was a review and report task. No package implementation, exported API, documentation source, or production tests were changed. Evidence scripts intentionally demonstrate the current defects; they are not tests of repaired behavior.

Scope and method

CRAN’s published package reference identifies 0.9.24, published 7 October 2026. The local 0.9.24 commit was used as the source comparison baseline; the CRAN source tarball was not independently compared byte for byte. Current source contains 86 R files and 51,766 lines including documentation. The baseline-to-HEAD diff changes 40 R files; across package code, documentation and tests it spans 111 files, 10,923 insertions and 1,039 deletions.

The review combined the post-CRAN source diff, broad module inspection, synthetic counterexamples, explicit controls, existing test execution, source-package construction, and R CMD check. Three parallel reviews were used under the repository’s inherited AGENTS.md instruction: sequence/input handling, inference/higher-order methods, and older estimation/clustering/MCML code. The primary reviewer separately examined the new landscapes and reran every reported defect from retained scripts. Prior audit notes were treated as leads, not as proof that an issue remained open.

This is broad review coverage with deeper scrutiny of changed code, not a claim that every one of 51,766 lines received equal inspection or that every statistical procedure was independently rederived. Static test mentions are an inventory aid, not measured code coverage. No fresh coverage percentage is claimed.

R01 · P1 — Numeric sequences with a logical missing position become ID sequences

Post-CRAN; incomplete input correction
R/build_network.R:1543–1551; R/extract_sequences.R:124

Observed behavior. For id=s1/s2, numeric T1/T3 and T2=NA, extraction returns id and T2. The resulting network has nodes s1 and s2; the actual states are metadata. This silently affects core estimation and every new sequence verb.

Why it happens. The numeric position-run detector requires is.numeric() for every position. An all-missing column created with NA is logical. The analogous categorical detector allows all-missing positions, but this branch does not.

Recommended correction / workaround. Allow all-missing columns within an otherwise numeric position run, while requiring evidence of numeric positions. Until fixed, supply cols=c("T1","T2","T3").

Regression test. Assert inferred and explicitly selected state matrices agree for numeric positions plus logical NA, with an ID column present. Check node labels as well as output dimensions.

d <- data.frame(id=c('s1','s2'), T1=c(1,2), T2=NA, T3=c(2,1))
extract_sequences(d)
build_network(d, method='relative')$nodes

Retained evidence: sequence-repros.R; sequence-repros.log

R02 · P1 — Post-hoc covariates determine the clusters they are tested against

Pre-existing at CRAN baseline; freshly reproduced
R/cluster_data.R:679–680, 738, 779–783

Observed behavior. Eight identical A→B sequences split perfectly into H and L groups when outcome is included in the raw frame and supplied as a post-hoc covariate. The function then reports outcomeL odds ratio 81. In this toy example the p-value is .0623; no significant result is claimed.

Why it happens. The entire raw data frame reaches sequence encoding and distance calculation before covariates are resolved. Outcome is treated as an extra sequence position, manufacturing the clustering signal. This violates post-hoc semantics.

Recommended correction / workaround. Resolve and remove named covariates before encoding, retain them separately, and preserve alignment. A network with covariates already in metadata, or a separate covariate data frame with sequence-only input, avoids this trigger.

Regression test. Changing a post-hoc covariate must leave the sequence distance matrix unchanged. Include constant true sequences and categorical/numeric named covariates.

d <- data.frame(V1=rep('A',8), V2=rep('B',8),
                outcome=rep(c('H','L'),each=4))
f <- build_clusters(d,k=2,covariates='outcome')
f$assignments # 1 1 1 1 2 2 2 2

Retained evidence: broad-repros.R; broad-repros.log

R03 · P1 — Loading uncertainty uses strength weights for an equal-weight fit

Pre-existing; earlier audit §6.2, still reproducible
R/mcml_pc.R:880–889

Observed behavior. An equal-weight composite has six observed loadings of 1/3. loading_stability() returns means .40279, .40214, .19507, .39981, .39849 and .20170; all six observed weights lie outside their bootstrap intervals. With fixed equal weighting, the resampled weights should remain 1/3.

Why it happens. Resamples call .pc_network_loadings() directly and do not replay x$meta$weighting or the weighting transformation. Confidence intervals therefore describe a different estimator. This also requires attention for eigen, factor and custom weighting.

Recommended correction / workaround. Replay the fitted weighting scheme in each resample. Preserve fixed weights for equal/custom schemes and refit only data-dependent schemes using their original settings.

Regression test. For equal weights, assert every draw is 1/cluster_size and bootstrap SD is zero. For fitted schemes, compare a deterministic resample with an explicit full rebuild.

# Full deterministic n=4000 fixture is in the evidence script.
f <- build_mcml_pc(d, clusters, aggregation='composite',
                   weighting='equal',method='cor',cor_method='pearson')
loading_stability(f,iter=30,seed=3)$summary

Retained evidence: broad-integration-repros.R; broad-integration-repros.log

R04 · P2 — Pattern outcome overwrites a real adjustment named .outcome

Post-CRAN new function; incomplete name-collision protection
R/pattern_outcome.R:150, 159

Observed behavior. For the same 39-row data, the pattern coefficient is .9285199 when adjusting for score. Renaming score to .outcome changes the coefficient to 8.9e-12. The function has replaced the adjustment with the outcome itself.

Why it happens. Vector and last_obs outcomes are written into units$.outcome before adjustment/group columns are extracted. Later internal model-column renaming protects other names but occurs too late for this collision.

Recommended correction / workaround. Keep the response separately or allocate a collision-free temporary name before modifying units. This also protects a grouping column named .outcome.

Regression test. Assert fitted coefficients are invariant when adjustment/group columns are renamed, including .outcome, for explicit vector and last_obs outcomes.

Retained evidence: sequence-repros.R; sequence-repros.log

R05 · P2 — Comparisons ignore node names when matrix orders differ

Pre-existing; earlier audit §4.3, still reproducible
R/compare_network.R:149–158

Observed behavior. Comparing a named matrix with a simultaneous row/column permutation of itself produces mean absolute difference 1.7777778 and Pearson .3809524, although both encode the same graph. Different named node sets of equal size are also accepted.

Why it happens. Only dimensions are validated; subtraction and correlation use matrix positions. Reordering a correctly labelled input silently changes the result.

Recommended correction / workaround. Align equal named node sets before computing statistics, and reject incompatible named sets. Retain a documented positional fallback for unnamed inputs.

Regression test. Compare a graph to its reordered self: all differences zero, Pearson one. Add incompatible-node and one-unnamed-input controls.

W <- matrix(c(0,1,2,3,0,4,5,6,0),3,3,byrow=TRUE,
            dimnames=list(LETTERS[1:3],LETTERS[1:3]))
compare_model(W,W[c(3,1,2),c(3,1,2)],network=FALSE)

R06 · P2 — Gaussian confidence intervals conflict with the displayed t tests

Pre-existing; earlier audit §5.12, still reproducible
R/outcome_model.R:249, 256–257

Observed behavior. For six observations, slope .6 has SE .2390457 and p=.06605877. The displayed nominal 95% interval [.131479,1.068521] excludes zero; the ordinary linear-model t interval is [-.06369732,1.26369732].

Why it happens. The Gaussian GLM estimates dispersion and reports Student t p-values. The effect-table code always uses qnorm() for intervals, yielding narrower intervals at small residual degrees of freedom.

Recommended correction / workaround. Use the appropriate residual-df t quantile for ordinary Gaussian fits. Treat binomial and mixed-model approximations explicitly.

Regression test. Compare ordinary Gaussian intervals against confint(lm(...)) across residual degrees of freedom; check consistency between zero inclusion and the unadjusted two-sided test.

d <- data.frame(x=1:6)
d$y <- .6*d$x+c(1,-1,0,0,-1,1)
outcome_model(d,'y','x',family='gaussian')$effects
confint(lm(y~x,d))

Retained evidence: broad-repros.R; broad-repros.log

R07 · P2 — Z centrality silently underflows to zero for large hyperedges

Post-CRAN numerical regression
R/hypergraph_centrality.R:251–257, 272–274

Observed behavior. A single uniform hyperedge of 150 nodes returns every Z entry as 7.606786e-163 and an L2 norm of zero, with no warning. The symmetry solution is 1/sqrt(150)=.08164966 per node. At 400 nodes all entries are zero.

Why it happens. The rewritten iteration squares a tiny tensor product before shifting/rescaling. Those squares underflow, and a zero norm is mistaken for an absent tensor. The earlier shift-first kernel preserves the symmetric solution on this example; that does not establish its correctness for all large graphs.

Recommended correction / workaround. Use stable normalization and scaled/log-domain products where needed; distinguish a true zero tensor map from floating-point underflow.

Regression test. Check analytic uniform solutions at 150 and 400 members and nonuniform rankings on an asymmetric large uniform graph. Assert nonzero unit norm and honest convergence diagnostics.

hg <- bipartite_groups(data.frame(player=1:150,group='G'),'player','group')
z <- hypergraph_centrality(hg,type='Z')$Z
range(z); sqrt(sum(z^2))

Retained evidence: inference-repros.R; inference-repros.log

R08 · P2 — Landscapes silently discard network weighting and concatenation

Post-CRAN new feature
R/stability_landscape.R:55–62, 90–95, 268–270

Observed behavior. A weighted transition network has A stay probability 1/3, but its landscape reports .4. A concat=3 network has stays A=2/3 and B=1/2, but its landscape reports .5 and 0. The discrepancy changes expected stays and depths. Landscape surfaces and trends use the same raw-sequence path.

Why it happens. The landscape reads stored sequences and pools unweighted adjacent counts without replaying build_args/params. Weighting changes the estimand; concatenation also changes transitions and the bootstrap units. The API describes a landscape of the supplied transition network.

Recommended correction / workaround. Faithfully replay supported estimation settings, or explicitly reject models with unsupported settings and document the required raw-data estimand. Do not silently return another chain.

Regression test. Assert full-length landscape stays agree with diag(network$weights) for weighted and concatenated fits, and verify bootstrap units/settings against an explicit reconstruction.

d <- data.frame(T1=c('A','A','B'),T2=c('A','B','A'))
n <- build_network(d,method='relative',params=list(concat=3))
diag(n$weights)
summary(stability_landscape(n,iter=0))[,c('state','stay')]

R09 · P2 — A nonconstant measure can create a collapsed surface axis and crash

Post-CRAN new feature
R/stability_landscape.R:447–451, 650–669, 692

Observed behavior. With 21 valid sequences, 20 alternating A/B and one A/A/B/A, entropy varies but its 5th and 95th percentiles are both 1. landscape_surface() returns 25 copies of one slice; plot() fails with invalid y argument.

Why it happens. Validation checks the full measure range, but the grid uses trimmed quantiles. Those endpoints can coincide for a discrete, strongly tied measure. Plotting deduplicates the values to one y coordinate, which persp() cannot render as a surface.

Recommended correction / workaround. Validate the actual grid endpoints; use a documented fallback range, a one-slice display, or a classed informative error. Avoid returning a nominal surface that its plot method cannot draw.

Regression test. Test nonconstant measures whose trimmed quantiles coincide. Check both summary semantics and plot execution, alongside constant-measure and ordinary continuous-measure controls.

s <- as.data.frame(matrix(rep(c('A','B','A','B'),each=21),nrow=21))
s[21,] <- c('A','A','B','A')
a <- landscape_surface(s,k=5)
plot(a) # invalid y argument

Retained evidence: landscape-probes.R; landscape-probes.log

R10 · P2 — MOGen summaries overflow the new double-precision parameter counts

Post-CRAN integration regression
R/mogen.R:768–769

Observed behavior. A valid 10-state fit through order 10 stores finite path DOFs of 9e9 and 9e10 for its last two layers. summary() returns NA for those layer counts and produces integer-coercion warnings. Model criteria remain finite; this finding concerns summary output rather than invalid fitting.

Why it happens. New path-based DOFs intentionally use doubles, but existing summary code casts them back to 32-bit integers. The new parameter-count representation was not propagated through the reporting API.

Recommended correction / workaround. Preserve numeric DOF columns in summaries and formatting. Check both layer and cumulative parameter counts.

Regression test. Include a small valid fit with parameter counts above .Machine$integer.max; assert returned counts match stored values without warnings.

set.seed(4)
s <- replicate(100,sample(LETTERS[1:10],14,TRUE),simplify=FALSE)
m <- build_mogen(s,max_order=10)
tail(m$layer_dof,2); tail(summary(m)$layer_dof,2)

R11 · P3 — Small but nonconstant strengths normalize to NaN

Post-CRAN numerical edge case
R/centrality_measures.R:222–229

Observed behavior. Public net_centrality() reports distinct incoming strengths of approximately 3e-12,1e-12,2e-12 but returns NaN for every normalized strength. The trigger involves extreme dwell/exit ratios and is lower priority than ordinary-input defects.

Why it happens. The new constant-vector tolerance is 1e-10 times max(abs(endpoints),1). The unit floor imposes an absolute threshold and classifies substantial relative variation at a small scale as constant.

Recommended correction / workaround. Use a scale-sensitive tolerance and handle exact constant vectors separately. Preserve min-max normalization under positive common rescaling.

Regression test. Test c(1,2,3) multiplied by several positive scales, plus exact-constant and rounding-noise vectors.

Retained evidence: broad-repros.R; broad-repros.log

R12 · P3 — Literal stars-only states collide with pattern wildcard parsing

Post-CRAN new function
R/sequence_patterns.R:463–464, 496

Observed behavior. Extraction accepts ** as a literal state. Unigram mining then raises an unclassed vapply error; bigram **→B receives lift .5 when its presence support .5 and state supports .5 and 1 imply lift 1.

Why it happens. The pattern parser removes stars-only tokens regardless of whether they were observed state labels or inserted wildcard positions.

Recommended correction / workaround. Either reserve/reject stars-only labels with a documented classed error or keep wildcard positions structurally distinct from state labels.

Regression test. Include ** and *** literals in unigram and bigram discovery, plus real gapped-pattern controls. Assert a correct result or a documented validation error.

d <- data.frame(T1=c('**','A'),T2=c('B','B'))
sequence_patterns(d,len=1,min_freq=1,min_support=0)
sequence_patterns(d,len=2,min_freq=1,min_support=0)

Separate design concern: reliability of existing edges versus the whole graph

R/casedrop_reliability.R:175–177 restricts the edge vector to cells nonzero in the original graph. The stated motivation—that subsampling cannot create an absent transition—holds for unthresholded transition counts. It does not hold for association or thresholded graphs. A deterministic thresholded-correlation example gains V1–V4=.3029003 and V3–V4=.2933043 after case removal. Reported max_abs_dev is .2854884 while whole-graph maximum deviation is .3029003. See inference-repros.R and its log.

The current help explicitly describes present-edge-only metrics, so this is kept outside the 12 defects: it is an implemented target with a material limitation. Decide whether the API should offer an explicit existing-edge/whole-graph target, or restrict the structural-zero rationale to methods for which it holds. A user assessing whole-network reliability should not infer that newly appearing edges have been included.

Compatibility and release readiness

The 1.0.1 NEWS correctly calls out three compatibility changes since 0.9.24: removal of the exported plot_mosaic name in favor of mosaic_plot; additional sequence_plot arguments after group, requiring later arguments by name; and clique-only default hypergraph_centrality output, with Z/H explicitly requested for uniform graphs. These are documented migration requirements, not findings of accidental regression.

The pkgdown reference configuration omits five documented topics: extract_sequences, long-data, pattern_outcome, sequence_metrics and sequence_patterns. This was already recorded in HANDOFF.md. Add them to the appropriate reference groups and rebuild the site. R-hub checking is manually dispatched; the automatic push/PR workflow builds pkgdown. A dedicated check workflow that explicitly runs the full non-CRAN development suite would give stronger ongoing protection than documentation CI alone.

A clean package check does not establish numerical correctness: all twelve defects were found using inputs outside the current assertions. Conversely, an earlier audit’s summary.mcml(compute_within=FALSE) crash was checked again and is now fixed; it is not listed as open. Existing fixed issues and intentional API changes were not recycled into the defect count.

Recommended work order

  1. Correct input-role inference, clustering covariate leakage, and loading-estimator replay (R01–R03). These can silently change what is being analyzed.
  2. Protect outcome adjustment names, align comparison nodes, and correct Gaussian intervals (R04–R06).
  3. Stabilize tensor normalization, make landscape estimation settings explicit, handle collapsed surface grids, and preserve MOGen counts (R07–R10).
  4. Resolve the two limited parser/scale edge cases (R11–R12), decide the case-drop target, and complete documentation indexing and CI coverage.
  5. After fixes, run the new invariant/oracle tests, the full development suite, the supported-platform checks and the relevant reverse dependencies. A passing test run alone should not close a finding unless its minimal counterexample now behaves correctly.
